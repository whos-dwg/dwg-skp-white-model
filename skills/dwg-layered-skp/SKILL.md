# DWG 分層 SKP 白模

將來自不同單位的 DWG／DXF 平面，依序完成來源解析、圖層與構件判讀、使用者核定、原生 SKP 生成及重新讀入檢查。每次來源建立獨立工作資料夾；來源圖層與構件語意分開保存，不要求來圖先改用本公司的圖層名稱。

## 通用判讀預設

- 已辨識的樓板開口折線／叉號，依其對應的實際區界先提出開口方案，不要求每個符號另有「留洞」文字。折線指開口標示符號，不是所有 LWPOLYLINE；板外框、房間及家具輪廓各按用途判讀。明確的降板／無孔說明、圖例或本案已核定覆寫優先，保留原符號、採用規則與修訂依據。
- 樓板缺少其他厚度依據時採 **200 mm** 白模預設，標示為預設值，無須為同一預設重問。來源或本次決策明示其他厚度時從其設定；有厚度衝突或明確特殊構造時局部處理，不用預設掩蓋矛盾。板域、作用樓層及標高仍須有依據。
- 樓板一律採真正整片、名義等厚的材料殼；外框、孔位及孔界維持來源／已核定輪廓。等厚不授權移孔、縮孔、補孔或移動外框；幾何無法同時成立時列具體衝突，不擅自改界。
- 牆、柱與全高帷幕一律收到當地上方樓板底，不因案件類型改變。保留原基底、門窗洞淨空及洞下窗台，不能為到板底而填住窗洞；跨板底高差按實際區域分段。缺上方板域／板底依據時列缺項，不套固定牆高。獨立欄杆及非全高配件仍按其用途取高。
- 樓梯間按整間範圍挖空，包含平台；由實際牆內邊與門檻等來源確定完整區界，不把梯段或定位框當孔界。範圍已固定，不再詢問是否包含平台；只有缺實際封閉界或作用板時才確認該缺項。各候選沿用可驗證的來源作用板證據、exact-ID決策或 `slabs.stair_opening_bindings`，不向所有 XY 相交的上下板一併扣洞，欄位見樓板契約。
- 防火門與防火捲簾的3D本體一律不建；仍讀取其2D門洞、門檻與分區證據，不因此保留堵住門洞的牆材或遺失樓板分區。
- 牆、柱的平面材料範圍依示意輪廓、實測線距、註記及用途判讀，不套用200 mm板厚或案例固定尺寸。
- 同一牆系的外包閉合線與內部閉合線若都被確認為牆界，牆材料取外圈扣除內圈的區域，內圈保留空腔；不能把每個閉合面都填滿。先分別核對來源線段的圖層、Z與平面性，非共面的3D線段不能無記錄地壓到XY後接成牆。
- 沿用可追溯的重邊、接點、閉合及精度修補：保存原幾何、影響範圍、容差與材料差異，於預覽前完成並驗證。具體微縫、容差及來源ID只存來源綁定的外部工作資料；不把異常畫法轉成新的製圖要求，也不以修補名義改變樓板外框或孔界。

以上為使用者固定的白模規範，適用所有新工作與採用新版規範的修訂；來源角色、標高與實際區界仍須證明。歷史核定及交付不自動改寫，案例數值不隨技能包發布。

## 入口與支援範圍

- 使用本 skill 的 `scripts/dwg_to_skp.py`；隨附 runtime、通用規則與 AutoCAD 抽取器，不依賴舊專案 work 或外部 E 槽。先執行 `doctor`。命令、決策欄位與錯誤處理見 [完整流程](references/workflow.md)。
- `inspect`／`review` 已接入逐葉件的自動平面辨識：牆材料與內腔、原生舊式2D／3D多段線、完整帷幕共用線網、全門扇／滑折門框、宿主牆厚過梁及樓板符號孔界，同時輸出 `recognition.json` 與整合檢查圖。辨識候選不是構造核定；仍看來源衝突、缺界及垂直尺寸，不以通過平面檢查冒稱已交付SKP。回歸檢查入口見完整流程。
- 使用者說「同步我目前選取的牆」、「直接改目前開啟的白模」或要以 CAD 選取局部修正時，切至獨立的 [dwg-skp-sync](../dwg-skp-sync/SKILL.md)，不讀取本技能的初次建模流程。此技能只負責初次建模與使用者明選的批次重建。
- DWG／DXF 由本機 AutoCAD Core Console 與隨附 .NET 唯讀抽取器解析；已有正規化 JSON 也可輸入。缺少引擎、單位、參照或不支援物件時回報具體原因，不以空模型或部分讀取宣稱成功。
- 通用成模範圍涵蓋單層平面的牆、柱、帷幕、具可確認輪廓與宿主的開口，以及分區水平 RC 樓板。樓板另用 [樓板推導、留洞與降板成模](references/rc-slabs.md)：主動結合平面外緣、標高與區域證據；slab-review 提出判讀，新工作在 decisions.slabs 完成樓板與板底收高方案後一併核定；已有核定建築工作才以 slab-attach 在獨立版本加入或修訂板域／分區／厚度，最後由同一 build 寫出並重讀 SKP。多份獨立 DWG 各自建立工作；外部參照保留來源身分。斜板、階梯本體、斜屋頂、AEC／代理物件與未能證明的構造列為參考／待確認，依已驗證的支援能力處理；樓梯本體不建不影響整間樓梯孔必須挖空。

## 解析與提出方案

1. 執行 inspect，核對來源及外部參照雜湊、讀取狀態、單位、模型空間、主要平面範圍與座標。單位不明時先問，不單憑圖面大小填入 mm。保留解析失敗與不支援清單。
2. 閱讀 layers.json、classification.json 及 review.svg。圖層名稱只是證據之一，結合幾何、圖塊、符號與空間關係提出分類；同層可有不同構件。分開保存原始物件圖層、插入圖塊圖層與有效圖層，保留圖塊實例路徑及世界座標。

   每個放置的巢狀圖塊都逐一檢視子 LINE／弧／輪廓的原始圖層與幾何，不以父圖塊圖層代替子件語意。父、子圖層導向不同構件用途時，保留雙方證據與受影響來源 ID，先提出局部確認，不能自行選邊或默默略過子件。盤點已解析的葉幾何與未建模來源，保留每個放置實例的完整ID及世界座標；父件已涵蓋的子件須去重。來源物件數、構件候選數與實際實體數分開統計。欄杆、立柱與帷幕配件按用途各自取高度。
3. 在 decisions.json 完成圖層映射及必要的物件覆寫，執行 review 更新候選輪廓。解決影響模型的未知用途、範圍、尺寸、厚度、開口與修補。可提出帶依據的候選值，不能把推定寫成使用者已提供。
   帷幕／建築外緣抽取後若仍有未閉合段，列出端點、缺線與受影響範圍，請使用者確認如何閉合；局部來源對齊修補須另記，不把推定補線當原圖。門洞辨識須涵蓋單扇、雙扇、滑門與折門等不同符號；由門框、兩側牆面與全部門扇判定洞口，不以第一片門扇或開啟弧決定全寬。
4. 展示彩色平面及核定摘要：原圖層對照、納入／參考／排除範圍、構件高度與基底、輪廓與洞口、未解決項目及圖層衝突。樓板要另外明示「本層腳下／牆上方」的作用對象；找到 H 註記與區域的對應，尚未證明其作用樓層。使用者更正作用對象時保留原始文字、來源圖層，重新對照標高、板域、孔洞與交界，不能只改 Z 或把兩層的孔洞對調。只詢問尚未核定且影響本次模型的內容，沿用本次來源已核定的決策。

   A.F.F. 分開記錄距離、單位、起算面及作用對象；已能由圖面確定的用途直接納入方案，不能一律略過或一律當RC板底。H±與A.F.F.分開解讀，不共用文字單位。樓板折線／叉號按開口預設判讀；降板及其他例外採更明確的來源或本案覆寫，各孔分別綁定作用板。建模前對照來源分布與實體覆蓋，逐筆記錄已建模／已涵蓋／參考／排除／待解；幾何QA不能代替來源完整性。

## 核定與建模

- 使用者明確同意目前預覽後，才用 approve 保存原話與該版本 review_sha256，再執行 build。升級 skill、測試流程、完成草稿或舊案例的同意，都不代表新圖面的建模核定。不得替使用者製造確認文字。
- 核定綁定來源／參照、正規化資料、規則、分類、決策、預覽及候選模型。來源或結果改變時建立新版本，重新檢查並確認受影響內容。不要繞過雜湊檢查或手改核定紀錄。
- 通用規則不得使用特定 handle／絕對座標補丁；使用者明確指定的單件修正存於本次 object_overrides，以完整來源物件 ID 綁定，不能污染通用規則。
- 建模只使用核定的 model.plan.json。清理重邊、近接端點、交接及修補須在預覽前完成並可追溯，不在寫出時另作分類或發明幾何。牆柱需為封閉實體，不用單張立面替代。
- RC 樓板以一般板／降板高程域與適用樓層開口準備方案；板厚按上述預設或明示值。所有新方案固定 whole_uniform_thickness，依 [樓板契約](references/rc-slabs.md) 檢查。不同標高的相接板邊核對連續性、板緣與實際厚度；整片必須是單一閉合材料殼，不能用父群組包裝分件冒充整併。缺標高、孔邊空間或特殊構造依據時保留完整預覽並阻擋，不以改孔、移外框或局部薄帶勉強完成。所有牆柱及全高帷幕自動按實際板底收高；實際板域外或留洞內須有來源支持的高度區投影，缺覆蓋不得保留任意原高。
- 單線牆缺厚度、閉合區域可能是房間、曲線不支援或門洞宿主不明時，保留來源參考並阻擋該方案核定，直到補充尺寸、指定輪廓或使用者明確改列參考／排除。不能填掉房間、管井或洞口。
- 過梁以門框定位，但平面範圍須延伸到兩側牆體的外側面、厚度對齊實際宿主牆厚；門扇或門洞矩形只表示淨空，不能直接充作過梁材料輪廓。兩側牆面或梁高無依據時只提候選並列缺項，不自造短梁或把預設門高冒稱來源。

## 依原圖層組織 SKP

- 每件構件獨立群組，葉群組的 Tag 使用原 DWG 圖層名稱；分類使用上層群組與屬性保存。原始邊與面均為 Untagged／Layer0。SketchUp 單一物件只能指定一個 Tag，不把來源＋語意誤作同物件多標籤。
- 圖塊內 Layer 0 預設採有效圖層作 Tag，同時保存原始 Layer 0、插入圖層與實例路徑；如使用者要字面原圖層，核定 source_tag_policy: original。其他原始圖層不任意改名。
- 不同來源同名圖層及 SketchUp 保留名稱使用可逆命名，交付 tag_mapping。構件含多個來源圖層時保留完整清單並要求核定主要圖層；可合理拆件時才拆分，不以複製重疊實體達成多圖層顯示。
- 保留來源 XY；本層地坪與 Z 基準、構件基底及高度須明示。樓板外框未畫出時依平面證據推導候選，不以「沒有封閉板框」直接判定資訊不足或略過樓板；標高、厚度、開口與降板仍須有來源或核定依據。未提供的天花、設備或其他構造不自動補造。

## 交付與修訂

- 必須重新讀入實際 SKP，獨立核對 Tag、可編輯群組、來源屬性、Untagged 原始幾何、座標／高度、封閉性、材料、實際板厚與體積；開口另核對宿主、淨空及上方構件。不能用規劃器自我重算代替實檔驗證。量板厚須依實際表面法向，轉角、孔緣與短段也納入；沿板身或轉折長度的射線不當成厚度。使用重新讀入結果製作預覽。
- 保存並核對 presentation.overhead_visible。新加入頂板的交付預設顯示頂板及立板，另供室內隱藏視圖；使用者另選顯示方式時從其設定。不能只檢查實體存在，卻讓開檔狀態看不到本次交付的頂板。
- 交付 SKP、核定摘要、原圖層對照、未建模／排除／修補清單及實際 QA。沒有通過必要檢查不得宣稱交付成功；幾何通過不代表語意及施工構造已獲證實。
- 使用 revise 另存新工作版本並重新執行受影響步驟；舊核定不隨版本複製，舊交付不覆寫。只有使用者選擇批次重建／另存版本時使用這條路徑。
